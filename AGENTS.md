# Project instructions

- Read AGENT_ROUTING.md first. Current stage: MVP building. Work from the scoped tasks in docs/implementation-plan.md and their handoff packets; do not scaffold or implement work outside an authorized task.
- Preserve seed/sources/ as original inputs. Record corrections in evidence or decisions rather than rewriting source history.
- Never invent product facts, APIs, research, or completion evidence. Distinguish sourced evidence, assumptions, proposals, and team decisions.
- Interviews are not required. Ask neutral questions one topic at a time; do not promote draft features into requirements without a team decision.
- Keep seed/market.md decision-useful: competitors, workarounds, strengths, limitations, and sourced opportunity hypotheses. A missing feature alone does not establish demand.
- Use one canonical home per fact; link instead of duplicating. Keep documents short and create later-stage specs only when needed.
- Log important choices, pivots, and scope cuts in docs/decision-ledger.md before updating affected specs.
- For every architectural decision or revision, log it in docs/decision-ledger.md first, then update docs/architecture.md and affected technical-spec/context/README references in the same change. Architecture owns the stack, system overview and diagram; technical-spec owns detailed data/API/execution contracts. Keep proposals and verified implementation distinct. Read seed/sources/velo-noir-builder-handbook.md for handbook content; retain the DOCX as the original.
- Product choices belong to the team. UI choices belong to the human designer unless explicitly delegated; see docs/design-brief.md.
- Before app/UI/copy changes, read guides/anti-slop-guardrails.md. Code must trace to a scoped handoff task once build work is authorized.
- docs/implementation-plan.md is the only task-status source. Task packets hold requirements and verification evidence, not separate status tracking.
- Read only relevant sections; make targeted edits. Load optional guides and skills when their subject applies.
- Use relevant installed skills when available; see guides/agent-skills.md. Their absence does not prevent reading the repository guides.
- Follow the team’s actual time budget and skills. The stated target is under 30 hours of MVP implementation with frontend and backend builders; the planning time budget is not yet decided.
